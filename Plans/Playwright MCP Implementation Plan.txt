## EXECUTIVE SUMMARY

This plan defines the architecture and implementation phases for building a browser-based Tableau→Power BI migration validation tool using Playwright MCP for browser automation and an AI agent for orchestration.

**Core Concept**: The AI agent (defined in agent.md/SKILL.md) orchestrates the validation workflow by calling Playwright MCP tools to interact with Tableau and Power BI reports in the browser.

**Key Differentiator**: Unlike your current FastMCP approach (which builds MCP servers), Playwright MCP PROVIDES browser automation capabilities that the AI agent can USE.

## PHASE 2: REPORT DISCOVERY & EXTRACTION (Week 2-3)
**Goal**: Extract all metadata, pages, visuals from both platforms

### 2.1 Page/Tab Discovery
- [ ] Create `src/services/tableau_extractor.py`
  - Detect all dashboard tabs: `.tabWidget .tab`, `.tableau-tab`, `[role="tab"]`
  - Navigate to each tab and wait for load
  - Return list of page names

- [ ] Create `src/services/powerbi_extractor.py`
  - Detect all report pages: `.pages-container .page-tab`, `[role="tab"]`
  - Navigate to each page and wait for load
  - Detect bookmarks panel for additional views
  - Return list of page names + bookmarks

### 2.2 Visual Discovery Per Page
- [ ] Tableau visual detection:
  ```javascript
  // JavaScript selectors (from SKILL.md)
  Array.from(document.querySelectorAll('.tabZoneViz, .tab-viz, [class*="tabVizZone"]'))
    .map((el, i) => ({
      index: i+1,
      title: el.querySelector('.tab-textRegion, .tabZoneTitle, text')?.textContent || `Untitled ${i+1}`,
      type: detectVisualType(el)  // Card, Table, Bar Chart, etc.
    }))
  ```

- [ ] Power BI visual detection:
  ```javascript
  Array.from(document.querySelectorAll('visual-container, .visualContainer'))
    .map((el, i) => ({
      index: i+1,
      title: el.querySelector('.visualTitle span, .visualTitle')?.textContent || `Untitled ${i+1}`,
      type: el.getAttribute('visual-type') || 'unknown'
    }))
  ```

### 2.3 Data Extraction by Visual Type
- [ ] **KPI Cards**: Extract title + numeric value
  - Tableau: `.tab-textRegion` with large font
  - Power BI: `.card .value`, `.cardValue`

- [ ] **Tables**: Extract all rows (handle scrolling!)
  - Tableau: Scroll `.tab-tvScrollY` to extract all rows
  - Power BI: Scroll `.mid-viewport` to extract all rows
  - Store: {headers: [], rows: [[val, val, ...], ...]}

- [ ] **Bar/Column Charts**: Hover each bar for tooltip values
  - Use systematic hover at bar center coordinates
  - Extract: {category, value, percentage}
  - Handle: scrollable charts, overlapping bars

- [ ] **Line/Area Charts**: Hover each data point
  - Extract: {x_value, y_value, series_name}
  - Handle: multiple series, dual axis

- [ ] **Pie/Donut Charts**: Special canvas hover (from SKILL.md)
  - Tableau: Sweep at multiple radii (35, 50, 65) with 5° increments
  - Power BI: Hover each `path.slice` element with PointerEvent dispatch
  - Extract: {category, value, percentage}

- [ ] **Filters/Slicers**: Extract filter values and states
  - Tableau: `.tab-filter`, `.tabQuickFilter`
  - Power BI: `.slicer-container`

### 2.4 Scrollable Visual Handling (CRITICAL)
- [ ] Implement iterative scroll extraction for tables
- [ ] Implement iterative scroll extraction for charts with many bars
- [ ] Track scroll position and extracted data to avoid duplicates
- [ ] Stop when 3 consecutive scrolls produce no new data

**Deliverable**: Complete data extraction from all visuals on all pages

## PHASE 3: COMPARISON ENGINE (Week 4)
**Goal**: Match visuals and calculate variances

### 3.1 Visual Matching
- [ ] Create `src/services/visual_matcher.py`
  - Exact title match (normalized: lowercase, trim, remove extra spaces)
  - Fuzzy match (character-level similarity > 80%)
  - Type + content match (same visual type with overlapping values)
  - Handle unmatched visuals separately

### 3.2 Variance Calculation
- [ ] Create `src/tools/variance_engine.py`
  - Numeric comparison: `abs(a-b) / max(abs(a),abs(b))`
  - Percentage comparison: `abs(a-b)` percentage points
  - Text comparison: case-insensitive exact match
  - Date comparison: normalize format then compare
  - Currency comparison: strip symbols, compare numeric

- [ ] Value normalization utilities:
  - Remove: $, €, £, commas, spaces
  - Convert: K→1000, M→1000000, B→1000000000
  - Handle: "2.27M" → 2270000

### 3.3 Classification Rules
- [ ] Implement pass/fail/warning thresholds:
  - 0% variance → Pass
  - < 0.5% variance → Warning
  - > 0.5% variance → Fail

- [ ] Create `src/orchestrator/decision_engine.py`
  - Apply rules to each comparison
  - Generate status for each visual
  - Aggregate dashboard-level accuracy

### 3.4 Filter & Drill-through Validation
- [ ] Create `src/tools/filter_validator.py`
  - Apply each filter combination in both platforms
  - Re-extract data after filter change
  - Compare filtered results

- [ ] Create `src/tools/drill_validator.py`
  - Navigate drill-through paths in both platforms
  - Compare drill-target visuals
  - Handle hierarchical navigation differences

**Deliverable**: Complete comparison with pass/fail/warning for each visual

## CRITICAL IMPLEMENTATION NOTES

### 1. Playwright MCP vs FastMCP
- **FastMCP**: Framework for BUILDING MCP servers (your current approach)
- **Playwright MCP**: Provides browser automation TOOLS for AI agents to USE
- **Decision**: Use Playwright MCP as the browser automation layer, NOT FastMCP

### 2. Browser Event Dispatching (CRITICAL)
- Tableau canvas charts require PointerEvent dispatch, not standard hover
- Power BI SVG elements require full event sequence (pointerenter → pointerover → pointermove)
- Standard `browser_hover` may NOT work for all visual types

### 3. Scrollable Visuals (CRITICAL)
- Both platforms use virtualized rendering for tables with many rows
- Only ~20-30 rows visible at a time
- MUST scroll iteratively to extract ALL data
- Stop when 3 consecutive scrolls produce no new data

### 4. Visual Count Enforcement (CRITICAL)
- Agent must extract EVERY visual, not just some
- Use numbered list approach: list all → extract each → verify count
- Report must show: N found, N extracted, N compared
- If counts don't match, go back and extract missing ones

### 5. Tooltip Extraction (CRITICAL)
- Tooltips are the PRIMARY source of truth for data values
- Data labels and axis text are SECONDARY confirmation
- MUST hover every data point in charts
- MUST handle canvas rendering in Tableau

## RISK ASSESSMENT

| Risk | Impact | Mitigation |
|------|--------|------------|
| Playwright MCP unavailable | High | Use direct Playwright API as fallback |
| Canvas rendering blocks extraction | High | PointerEvent dispatch (documented in SKILL.md) |
| Platform updates break selectors | Medium | Fuzzy matching + multiple selector fallbacks |
| Login required for reports | Medium | Report in output, skip authentication |
| Large dashboards timeout | Medium | Configurable timeouts + progress logging |
| Visual count mismatch | High | Enforced numbered list approach |
